# AI 编程指南：数据验证与弱耦合架构 (通用版) ## 一、核心通用原则 *这些原则适用于所有语言，是 Agent 架构设计的“宪法”。* ### 1. Schema-First Design (契约优先) - **定义：** 任何模块间的交互，必须先定义数据结构，后编写逻辑。 - **目的：** 将“数据是什么”与“代码怎么做”彻底解耦。 - **执行：** 禁止在函数参数中使用 `any`, `dict`, `object` 等泛型作为数据载体。必须定义明确的 Schema Class。 ### 2. Runtime Validation (运行时防御) - **定义：** 外部输入（API、文件、用户输入）默认不可信，必须在系统边界进行强校验。 - **目的：** 防止脏数据污染核心业务逻辑。 - **执行：** 校验逻辑不应散落在业务代码中，应集中在 Schema 定义处。 ### 3. Structural Coupling (结构耦合) - **定义：** 模块 A 依赖模块 B 的数据结构，而不依赖模块 B 的具体实现类。 - **目的：** 实现弱耦合。只要数据结构不变，模块 B 可以随意重构、替换技术栈甚至重写语言。 --- ## 二、技术栈映射规则 *根据目标语言，选择对应的工具库实施上述原则。* ### 1. Python 技术栈 - **核心工具：** `Pydantic (v2)` - **Schema 定义：** 继承 `BaseModel`。 - **类型系统：** 利用 Python Type Hints。 - **关键特性：** - `field_validator`: 字段级逻辑校验。 - `model_validator`: 对象级交叉校验。 - `model_dump()`: 序列化输出。 - `Config(extra='forbid')`: 严格模式，拒绝非法字段注入。 ### 2. TypeScript / JavaScript 技术栈 - **核心工具：** `Zod` (或者 TypeBox, Yup，推荐 Zod) - **Schema 定义：** 使用 `z.object({...})`。 - **类型系统：** 使用 `z.infer<typeof Schema>` 自动推导 TS 类型，实现“Single Source of Truth”。 - **关键特性：** - `.parse()`: 解析与校验（失败抛出 ZodError）。 - `.safeParse()`: 安全解析（返回 Success/Fail 对象，不抛异常）。 - `.transform()`: 校验同时进行数据清洗/转换。 - `.strict()`: 严格模式，禁止未知键。 ### 3. 映射对照表 | 架构动作 | Python (Pydantic) | TypeScript (Zod) | | :--- | :--- | :--- | | **定义模型** | `class User(BaseModel):` | `const UserSchema = z.object({` | | **字段定义** | `name: str` | `name: z.string()` | | **可选字段** | `age: Optional[int] = None` | `age: z.number().optional()` | | **类型推导** | (IDE 自动补全) | `type User = z.infer<typeof UserSchema>` | | **数据校验** | `User(**data)` (构造时自动校验) | `UserSchema.parse(data)` | | **严格模式** | `model_config = Config(extra='forbid')` | `UserSchema.strict()` | | **序列化** | `model.model_dump()` | `UserSchema.parse(data)` (返回纯净对象) | --- ## 三、Agent 执行禁令 *无论使用何种语言，Agent 必须遵守以下红线：* 1. **禁止隐式 `any` / `dict`：** - Python: 禁止 `def process(data: dict):` - TS: 禁止 `function process(data: any):` - *修正：* 必须定义对应的 Schema Model。 2. **禁止“信任传递”：** - 数据从模块 A 传给模块 B，如果未经过 Schema 校验，视为架构错误。 3. **禁止逻辑与校验混杂：** - 不要在业务函数开头写一堆 `if not data.email: raise Error`。 - *修正：* 将此逻辑移至 Schema 的 validator 定义中。
