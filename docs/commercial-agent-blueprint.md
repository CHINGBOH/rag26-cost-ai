# 工程商务 Agent 蓝图

## 1. 顶层定位

本仓库的产品定位从“单一造价知识问答系统”升级为：

> **私有化优先的工程商务 Agent**

它服务的不是泛泛的项目管理，而是工程企业最核心的商务链路：

```text
商机判断 → 招标文件审查 → 报价与投标协同 → 废标风险防控 → 合同关键条款审查 → 商务向执行移交
```

用户的核心工作角色更接近：

- 商务员 / 商务经理
- 投标专员
- 报价与接单负责人
- 合同签订前的业务把关人

第一阶段不试图一次做完全链路，而是从最痛、最容易证明价值的环节切入：

> **投标废标风险审查**

## 2. 为什么第一刀切“废标风险审查”

该模块具备非常适合 Agent 落地的特征：

- 文档密集
- 条款复杂
- 细节容错率极低
- 一处失误即可直接废标
- 客户能立刻判断系统是否有用

典型风险：

- 董事长 / 法定代表人要求签字，却误做成盖章
- 授权委托书主体或格式错误
- 附件、业绩、社保、财务材料遗漏
- 投标保证金到账时间理解错误
- 正副本份数、密封、电子签章、逐页签章不合规

## 3. 产品总体模块

### A. 商机判断 Agent（后续）

输入：招标公告、项目摘要、客户线索。

输出：

- 是否值得投
- 资质初筛
- 项目规模与竞争强度判断
- 预估准备成本
- 是否建议继续深入

### B. 投标废标风险审查 Agent（当前主线）

输入：招标文件、补遗、答疑、可选企业响应文件。

输出：

- 一票否决项 / 废标项
- 签字盖章审查表
- 必交附件清单
- 时间节点清单
- 保证金 / 保函要求
- 需澄清条款

### C. 报价与投标协同 Agent（后续）

输入：清单、图纸说明、历史报价、成本规则。

输出：

- 报价拆解
- 风险项提示
- 需向技术 / 采购确认的问题
- 版本差异核对

### D. 合同关键条款审查 Agent（后续）

输入：拟签合同、招标文件、澄清纪要、商务谈判版本。

输出：

- 回款与付款节点
- 违约责任
- 质保 / 履约保证金
- 工期与延误责任
- 是否与招标文件或报价口径冲突

### E. 商务向执行移交 Agent（后续）

输出项目移交包：

- 中标关键承诺
- 合同红线条款
- 报价边界
- 甲方特殊要求
- 执行中不得遗漏的商务节点

## 4. 私有化优先原则

工程商务文档高度敏感。仓库默认遵循：

1. 文档默认不出客户内网
2. OCR、向量库、审查结果可本地化
3. LLM Provider 可替换：本地模型、客户自有模型服务、企业级 API
4. 高危结论必须给原文证据，不做无出处判断
5. 系统提供“风险预审”，不替代最终人工签署责任

## 5. 当前仓库能力复用

现有 `rag26-cost-ai` 已具备：

- 文档 OCR 与解析底座
- RAG 检索链路
- 混合召回与 Rerank
- LangGraph Agent
- 结构化工具调用
- Docker / 服务化部署框架

这些能力可直接承接工程商务 Agent，不需要推倒重来。
