# 文档索引机制

## 索引的概念与意义

索引在 RAG 系统中的作用，类似于给图书馆里的每本书制作"书目卡片"，并按主题分类归档。没有索引，即使有再多文档，系统也无法快速找到相关内容。RAG 智库系统的索引过程把 PDF 等原始文档转变为可被语义检索的向量，存入四个数据库，让每段内容都能被"按意思找到"，而不仅仅是按关键词匹配。

## 完整索引六步流程

文档从上传到可查询需要经历六个步骤。第一步，上传：用户通过"数据管道"页面上传 PDF、Word、TXT 或 Excel 文件。第二步，解析与 OCR：OCR 服务（PaddleOCR）处理 PDF，识别文字内容，保留原始页码和布局信息；如果是扫描件，还需要图像识别文字。第三步，分块（Chunking）：将长文档按语义边界切分成 300-500 字的文本块，保证每块内容完整且不过长（过长的上下文会稀释向量的语义焦点）。

## 嵌入向量化与入库

第四步，嵌入向量化：BGE-M3 模型（通过 TEI 服务运行在端口 8003）将每个文本块转换为 1024 维的浮点数向量，这个向量捕捉了文本的语义含义。第五步，写入四库：Qdrant 存向量（用于语义检索）；PostgreSQL 存文本内容 + 元数据（用于精确查询和结构化检索）；Elasticsearch 建分词倒排索引（用于关键词精确匹配）；Neo4j 提取概念节点和关系边（用于知识图谱推理，可选步骤）。第六步，完成：文档状态更新为"已索引"，可以参与检索。

## 嵌入模型 BGE-M3

系统使用的嵌入模型是 BGE-M3（BAAI General Embedding，M3 代表 Multi-Lingual、Multi-Functionality、Multi-Granularity），这是百川智能开源的多语言向量模型。主要特点：原生支持中文，中文语义理解优秀；1024 维向量，表达能力强；同时支持稠密检索（向量相似度）和稀疏检索（BM25）；适合长文本（支持 8192 token 输入）。所有业务文档和系统内部知识库都使用同一个模型嵌入，确保向量空间一致。

## 索引进度监控

文档索引是异步后台任务，用户上传后可以在"数据管道"页面查看实时进度。进度包括：当前处理阶段（OCR/分块/向量化/写库）、已完成文本块数量、预计剩余时间。系统运维页面提供汇总视图：总索引文档数、总文本块数（chunks）、各数据库健康状态。大型 PDF（几百页的规范文件）可能需要 5-15 分钟完成索引，扫描件 PDF 因为需要 OCR 时间更长。

## 特殊文档处理

不同类型的文档有特殊处理逻辑。PDF 扫描件：PaddleOCR 识别图像文字，精度取决于扫描质量，清晰扫描件识别率 95% 以上。Excel 价格表：自动识别表格结构，提取材料名称、规格、价格等字段，直接写入 price_records 结构化表，同时也生成文本块供语义检索。Word 文档（.docx）：解析段落和表格，保留标题层级结构，有助于规范条文的条款结构识别。同名文档重新上传：系统按 doc_id 去重，重复上传会更新现有记录而非创建副本，避免重复索引导致检索结果重复。
