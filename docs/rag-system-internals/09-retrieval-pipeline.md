# 完整检索与推理流水线

## 第一步：查询分析与意图识别

用户提问后，QueryAnalyzer 首先分析查询意图和类型。它识别问题属于哪种类型：价格查询（需要 price_query）、费率标准查询（需要文档检索）、条文规范查询（需要 rule_clause_search）、计算问题（需要检索 + 计算）、综合分析问题（需要多工具组合）。同时提取关键实体：材料名称、规格型号、时间范围、工程类别、计税方式等。这一步决定了后续工具调用的策略，避免用错误的工具浪费时间。

## 第二步：查询改写与扩展

原始用户问题往往不够精确，QueryAnalyzer 会生成多个扩展查询。例如用户说"水泥贵不贵"，系统扩展为"普通硅酸盐水泥 P.O42.5 信息价 深圳 2026"等更精确的查询变体。对于附录标准类问题（is_appendix_standard_query），系统提取标准条款的关键术语做精确匹配。对于费率标准对比类问题（is_fee_standard_comparison_query），系统生成包含不同计税方式的多个查询。查询改写是提高召回率的关键步骤，好的改写能让检索结果从"找不到"变成"精准命中"。

## 第三步：多路并行检索

Agent 根据查询分析结果，同时向多个数据源发起检索。hybrid_search 工具并行调用 Qdrant 向量检索（语义相似度）、PostgreSQL pgvector（快速近似最近邻）和 Elasticsearch（分词全文匹配），三路同时返回各自的 top-K 候选段落。对于价格类问题额外调用 price_query 直接从价格表获取精确数据。对于概念关联问题额外调用 concept_search 从 Neo4j 获取图结构信息。多路并行确保不遗漏任何可能相关的内容。

## 第四步：RRF 融合排名与去重

多路检索结果通过 RRF（互惠排名融合）算法合并。RRF 公式：每个段落的融合分 = Σ(1/(k + rank_i))，其中 k=60（常数），rank_i 是该段落在第 i 路检索中的排名。这个算法不受各路检索绝对分数量纲差异的影响，只看排名位置。合并后对完全相同内容去重（同一 chunk_id），产出全局最优排名列表。这是 RAG 系统中"多路融合"的核心，效果通常优于任何单一检索方式。

## 第五步：重排序精化

经过 RRF 融合后的 top-N 候选段落，再经过重排序（Rerank）模型二次打分。重排模型比初步检索的向量相似度更精准，它以"查询-段落对"为输入，直接输出相关性分数。系统设置的相关性阈值为 0.60：低于此阈值的段落会被过滤掉，不会进入 LLM 上下文。重排序是精度提升的关键步骤，过滤掉了初步检索中"差不多相关"但实际价值不高的噪声内容。

## 第六步：LLM 生成答案

重排后保留的高质量段落被组装成 system prompt 注入 LLM。LLM 使用的模型是 deepseek-v4-flash，具有 100 万 token 的上下文窗口。系统 prompt 明确要求：基于提供的参考内容作答，不得猜测未在参考内容中出现的信息，对不确定的内容要明确说明不确定。答案通过 SSE（Server-Sent Events）流式输出，用户可以实时看到答案逐字出现，无需等待完整生成后才显示。

## 第七步：置信度评估与来源溯源

答案生成后，系统从四个维度评估综合置信度：完整性（检索到的内容是否覆盖问题的全部关键点）、一致性（多个参考段落之间是否相互印证）、事实一致性（生成的答案是否与参考段落吻合）、来源多样性（是否有多份独立文档佐证）。综合置信度低于 0.60 时，系统明确返回"当前知识库中的信息不足以完整回答此问题"，并说明可能的原因。每个答案同时返回来源文档 ID、章节、页码，支持溯源验证。

## ReAct 迭代推理循环

Agent 采用 ReAct（Reason + Act）范式，这是一种"思考→行动→观察→再思考"的循环机制。Agent 不是一次性生成答案，而是：1）分析问题，制定行动计划；2）选择并调用一个工具；3）观察工具返回结果；4）判断信息是否足够；5）如不够，再次思考，选择下一个工具；6）重复直到能给出完整答案或达到最大迭代次数。这让 Agent 可以根据中间结果动态调整策略，处理复杂多步骤问题。默认最大迭代次数为 3，专业版用户可调整。
