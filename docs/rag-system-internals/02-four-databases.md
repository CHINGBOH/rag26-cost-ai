# 四库数据库架构

## Qdrant 向量数据库

Qdrant 是系统的语义检索核心，运行在端口 6333。它存储每段文档文本对应的 1024 维嵌入向量。嵌入向量是文本"语义含义"的数学表示，相似含义的文本，其向量在高维空间中距离近。Qdrant 使用余弦相似度（Cosine）度量相关程度。主集合 document_chunks 存储业务文档，agent_lecture_kb 存储内部技术文档，rag_system_kb 存储系统导览知识库。每次语义检索时，系统把用户问题也转成 1024 维向量，然后在 Qdrant 中找最近邻。

## PostgreSQL 关系数据库

PostgreSQL 是系统的主数据库，运行在端口 5432。它存储文档元数据（documents 表）、文本块（chunks 表）、价格记录（price_records 表）、用户会话（sessions 表）和 Agent 运行日志（agent_runs 表）。价格查询工具直接从 price_records 表读取含税价、不含税价、规格型号、来源月份等结构化数据。PostgreSQL 还支持 zhparser 中文分词，可以做全文模糊检索。所有精确数字查询（价格、费率、统计）都优先走 PostgreSQL。

## Neo4j 知识图谱数据库

Neo4j 是系统的关联推理引擎，运行在端口 7687。它存储概念节点和关系边，例如"企业管理费"→属于→"间接费"→属于→"建设工程造价"。当用户问"A 和 B 是什么关系"或"从某个概念出发，相关的知识有哪些"时，Neo4j 的图路径检索工具就发挥作用。topology_search 工具可以沿图边推理多跳关系（默认深度 2），concept_path 工具可以找两个概念之间的最短路径。

## Elasticsearch 全文检索引擎

Elasticsearch 是系统的精确术语检索引擎，运行在端口 9200。它为每个文本块建立分词倒排索引，支持中文分词精确匹配。当用户使用行业专业术语（如特定规范条款编号、精确材料名称）提问时，Elasticsearch 的命中率最高。它使用布尔检索，要求词汇精确出现，与向量检索形成互补——向量检索擅长"意思相近"，全文检索擅长"词汇精确"。

## 四库协同 RRF 融合机制

hybrid_search 工具同时向 Qdrant、PostgreSQL（pgvector 近似检索）和 Elasticsearch 发起查询，各自返回候选段落后，用 RRF（互惠排名融合，Reciprocal Rank Fusion）算法合并排名。RRF 不依赖绝对分数，而是用各路检索的排名位置加权，避免了不同检索系统分数量纲不同的问题。最终产出一个综合排名列表，比任何单一检索方式都更全面准确。

## 数据库健康监控

系统运维页面会实时显示四个数据库的健康状态。任何一个数据库出现故障，系统会自动降级：如果 Qdrant 不可用，降级为仅 PostgreSQL + Elasticsearch 检索；如果 Neo4j 不可用，跳过图检索工具。降级模式下系统仍可运行，只是部分检索能力下降。健康检测每 30 秒执行一次，状态变化通过 WebSocket 实时推送到前端。
