# RAG 智库系统 — 总体架构

## 系统定位与用途

RAG 智库系统是一套面向建设工程造价行业的企业级知识问答平台。系统的核心价值是让用户用自然语言提问，系统自动在已上传的造价文档、信息价文件、费率标准中找到准确答案，而不是依赖 AI 凭空猜测。用户只需提问，不需要记忆文档在哪里、格式是什么，系统替用户做检索、推理和计算。

## 五个核心服务进程

系统由五个后端服务组成，各司其职。Go 网关（端口 8080）是统一入口，所有前端请求都先到这里再被转发。Python 检索服务（端口 8002）是最核心的服务，负责 Agent 推理、工具调用和 RAG 流水线。Python 历史服务（端口 8000）负责文档上传、嵌入索引和历史记录。Go WebSocket（端口 8081）负责实时状态推送。Node.js 协调器（端口 3000）使用 XState v5 状态机管理会话。React 前端（端口 5173 或 8888）是用户界面。

## 请求完整链路

用户在浏览器输入问题后，请求路径如下：浏览器 Vite Proxy → Go 网关（8080）→ Python 检索服务（8002）→ Agent 决策循环（选择工具、调用工具、分析结果）→ 四个数据库并行查询 → LLM 生成最终答案 → SSE 流式推送 → 浏览器实时显示。整个过程通常需要 3-15 秒，取决于问题复杂程度和工具调用次数。

## 前端三大功能模块

前端有三个主要交互界面。企业知识库页（首页）是极简对话界面，适合日常查询，隐藏所有技术参数。RAG 问答专业版是三列布局界面，左侧设置参数，中间对话，右侧实时显示 Agent 推理过程、工具调用轨迹和检索来源。系统运维页面显示各服务健康状态、文档数量统计和索引进度。

## 技术栈概览

前端使用 React 18 + Vite + Zustand（状态管理）+ TanStack Query（服务端数据）。Go 网关使用 Gin 框架做反向代理。Python 检索服务使用 FastAPI + LangChain 工具体系。嵌入模型通过 TEI（Text Embeddings Inference）服务运行，产出 1024 维向量。LLM 使用 DeepSeek API（deepseek-v4-flash，100 万上下文窗口）。

## 系统名称与设计理念

系统俗称"四库"，因为同时使用四种数据库协同工作。这个设计借鉴了《四库全书》的思想——多角度收录知识，让查询更全面。向量数据库负责"理解意思"，关系数据库负责"精确数字"，图数据库负责"关联推理"，全文检索引擎负责"精确词汇"，四者互补。
