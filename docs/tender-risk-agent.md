# 投标废标风险审查 Agent

## 1. 模块定位

该模块是“工程商务 Agent”的第一可落地产品切口：

> **在正式制作和递交投标文件前，先用机器完成一次高召回的废标风险扫描。**

它优先解决商务员、投标专员和商务经理最怕的问题：

- 有没有一票否决项被漏掉
- 哪些地方必须签字，哪些地方必须盖章
- 董事长 / 法定代表人 / 授权代表到底谁签
- 附件、社保、业绩、财报、承诺函是否缺项
- 保证金、保函、截止时间是否有硬要求
- 正副本、密封、装订、电子签章是否有特殊规定

## 2. 私有化优先

投标文件和商务资料属于企业核心敏感文档。因此本模块默认遵循：

- 文档解析尽量本地化
- 审查结果保存在客户内网
- LLM Provider 可替换，不强绑定公有云
- 每条高危结论必须附原文证据
- 系统做“风险预审”，不替代最终人工签署责任

## 3. 第一阶段 MVP

### 输入

- 招标文件文本
- 后续接入：PDF / Word / 补遗 / 答疑

### 输出

一份结构化风险清单，包含：

- 风险分类
- 严重度
- 风险标题
- 要求摘要
- 原文证据
- 为什么重要
- 建议动作
- 是否需要人工复核

## 4. 当前已落地接口

### `GET /api/v1/commercial/tender/rule-catalog`

返回第一版规则库，便于测试与演进。

### `POST /api/v1/commercial/tender/review-preview`

对已解析文本进行规则预扫。

示例请求：

```json
{
  "document_name": "某项目招标文件.txt",
  "max_hits_per_rule": 4,
  "text": "投标文件须由法定代表人签字并加盖公章，否则作无效投标处理。"
}
```

示例输出关注：

- `critical_count`
- `high_count`
- `risks[].category`
- `risks[].evidence.excerpt`
- `risks[].recommended_action`

## 5. 第一版规则库类别

- 否决投标 / 无效投标
- 签字与盖章
- 资格条件
- 必交附件
- 时间节点
- 保证金 / 保函
- 份数 / 密封 / 装订 / 电子签章

## 6. 推荐下一阶段

下一步应将现有规则预扫与仓库既有 RAG / Agent 能力接通：

```text
文件上传
  ↓
OCR / 解析
  ↓
章节切分与索引
  ↓
规则预扫
  ↓
按风险类型触发专项检索
  ↓
LLM 做语义审查
  ↓
输出完整审查报告
```

## 7. 评估集建议

应优先收集历史真实样本：

- 因签字盖章错误废标
- 因附件遗漏废标
- 因保证金 / 截止时间问题废标
- 因密封 / 电子签章 / 正副本问题废标

目标不是一开始追求“完全自动替代”，而是验证：

> **系统能否提前发现曾经真实发生过的废标原因。**
